# 03 · 页面原型与交互流程

**版本：** v0.2.2
**配套可视化原型：** `prototypes/prototype.html`（浏览器直接打开）
**视觉规范：** 见 [《07 视觉设计规范》](07-视觉设计规范.md)（本文档第七章只保留摘要）

**v0.2.2 勘误：** P08 / P09 的重复选项由「不重复 / 每天 / 每周」改为
**「不重复 / 每周 / 每月」** —— 原稿与 PRD §6.3 直接矛盾：那里明确把「每天」
划到 V0.2（一年 365 次，订阅额度撑不住；且高频重复实质上接近「自动催办」，
与「少打扰」原则冲突），同时 V0.1 是**支持每月**的。另补两处实现约定：
重复的周几 / 几号由「什么时候」推出，不单独再问一遍；P09 的「重复」与
「叮一下」在未定时间时一起置灰。

**v0.2.1 变更摘要：**

## 一、信息架构

> **v0.2 变更：** 底部导航由 3 个 Tab 扩展为 **4 个**，新增「👤 我的」。
> 原先挂在首页右上角的「家庭」入口整体搬进「我的」，为 V0.2 的「切换家庭」预留位置。
> 本节已与《产品需求文档》5.1 / 5.3 对齐。

```text
家有小事
│
├── 启动 / 登录（非 Tab）
│   ├── 授权登录页
│   ├── 创建家庭
│   ├── 加入家庭
│   └── 填写家庭称谓
│
├── 🏠 家里（Tab 1）
│   ├── 首页
│   ├── 叮一下（创建提醒）
│   ├── 派活（创建任务）
│   ├── 小事详情
│   └── 我的小事
│
├── 🍽️ 吃啥呢（Tab 2）
│   ├── 决定页（卡片）
│   ├── 菜谱列表
│   └── 菜谱管理
│
├── 📖 留个念（Tab 3）
│   ├── 家庭时间线
│   ├── 发布记录
│   └── 记录详情
│
└── 👤 我的（Tab 4）
    ├── 家庭信息
    ├── 家庭成员
    ├── 邀请成员
    ├── 家庭设置
    ├── 消息中心
    ├── 微信提醒（绑定 / 解绑）
    ├── 隐私政策
    └── 注销账号 / 退出家庭
```

**底部导航 4 个 Tab：家里 / 吃啥呢 / 留个念 / 我的。**
「叮一下」和「派活」是**动作**，不是内容频道，作为首页的悬浮高频入口存在。
**「消息中心」也从首页铃铛移入「我的」**——首页只负责「今天家里有什么事」，不再承担通知归档。

## 三、页面详细设计

### P01 首页 `pages/index/index`

**设计目标：** 打开之后，马上知道今天家里有什么事。

```text
┌──────────────────────────────┐
│ 我们家 👨‍👩‍👧                     │  ← 纯展示当前家庭上下文，不可点击
│ 9月28日 周一 · 今天家里有什么小事？│     （家庭管理入口已移至「我的」Tab）
├──────────────────────────────┤
│                              │
│   ┌──────────┐ ┌──────────┐  │
│   │  🔔      │ │  🎯      │  │  ← 两个高频动作入口（大按钮）
│   │ 叮一下   │ │ 派个活   │  │
│   └──────────┘ └──────────┘  │
│                              │
├──────────────────────────────┤
│  🔔 今天的提醒           更多 →│
│                              │
│  17:30  接宝宝      阿妈      │
│  18:00  拿快递      阿爸  ✓   │
│                              │
├──────────────────────────────┤
│  🎯 最近的活             更多 →│
│                              │
│  🛒 买菜          阿妈  待完成 │
│  🚗 洗车          阿爸  待完成 │
│                              │
├──────────────────────────────┤
│  ┌────────────────────────┐  │
│  │      🍽️  吃啥呢         │  │  ← 单行卡片，点击进 Tab2
│  │      今天吃什么？        │  │
│  └────────────────────────┘  │
├──────────────────────────────┤
│  ┌────────────────────────┐  │
│  │  📖 留个念              │  │  ← 最新一条记录预览
│  │  宝宝今天第一次自己穿鞋   │  │
│  │  阿妈 · 昨天 19:32      │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
│ 🏠 家里 │ 🍽️ 吃啥呢 │ 📖 留个念 │ 👤 我的②│
└──────────────────────────────┘
```

**元素与交互：**

| 元素 | 交互 | 跳转 |
| --- | --- | --- |
| 家庭名 | **不可点击**，仅作上下文提示 | — |
| 🔔 叮一下 | 点击 | → P08 叮一下创建页 |
| 🎯 派个活 | 点击 | → P09 派活创建页 |
| 今日提醒条目 | 点击 | → P10 小事详情 |
| 提醒条目右侧 ✓ | 点击 | 直接完成，卡片划出动画 |
| 「更多」 | 点击 | → P11 我的小事（带筛选） |
| 吃啥呢卡片 | 点击 | 切换 Tab 到 P02 |
| 留个念卡片 | 点击 | → P19 记录详情 |

> **v0.2 变更：** 首页**不再有铃铛和家庭入口**。
> - 消息中心 → 移入「我的」Tab（P12）
> - 家庭信息 → 移入「我的」Tab（P13）
> - 未读通知数 → 以角标形式挂在底部「我的」Tab 上
>
> 理由：符合小程序用户习惯（设置类内容都在「我的」），并为 V0.2 的「切换家庭」预留了天然位置。
> **首页只做一件事：回答「今天家里有什么事」。**

**接口：** `GET /family-things/today` + `GET /notifications/unread-count`（合并成一次，或并行）

**状态：**

- **加载中**：骨架屏（灰色占位块），不用转圈
- **空状态（新家庭）**：两个大按钮下方出现引导
  ```text
  📭 今天还没有小事
  要不要先叮一下阿妈？
  ```
- **有人没开微信提醒**：顶部出现一条轻提示条（仅在**自己是发起人**且对方未绑定时出现）
  ```text
  ⚠️ 阿妈还没开微信提醒，她打开小程序才能看到。去帮她开一下 →
  ```
  > 点击 → P21 微信提醒页。注意文案**不能是催办语气**，只陈述事实 + 给一个轻量出口。
- **订阅额度不足**（辅助通道）：若订阅消息是当前唯一可用通道且额度 < 2
  ```text
  ⚠️ 提醒快用完了，点一下补上 →
  ```
- **下拉刷新**：重新拉取今日数据

### P08 叮一下 `pages/nudge/create`

**设计目标：** 3 步内完成，尽量少的输入。

```text
┌──────────────────────────────┐
│  ←  叮一下                    │
├──────────────────────────────┤
│  叮谁？                       │
│  ┌────┐ ┌────┐ ┌────┐        │
│  │阿妈│ │阿爸│ │阿公│        │  ← 头像 + 称谓，单选
│  └────┘ └────┘ └────┘        │
│                              │
│  叮什么？                     │
│  ┌────────────────────────┐  │
│  │ 明天记得给宝宝带水杯     │  │  ← 大输入框，自动聚焦
│  └────────────────────────┘  │
│  常用：带水杯 / 拿快递 / 交费  │  ← 快捷短语（历史记录生成）
│                              │
│  什么时候叮？                 │
│  ⚪ 现在就叮                  │
│  ⚫ 定时叮                    │
│     明天 07:00        修改 >  │
│                              │
│  要不要重复？                 │
│  ⚪ 不重复  ⚪ 每周  ⚪ 每月   │
│  每周六 09:00                 │  ← 周几由「什么时候」推出，只读回显
│                              │
├──────────────────────────────┤
│        [  叮 一 下  ]         │
└──────────────────────────────┘
```

**交互细节：**

1. 进入页面**自动聚焦输入框**，直接弹键盘（减少一次点击）
2. 输入框上方实时显示「将发送给：阿妈」
3. 「常用」短语来自该用户历史创建的提醒标题 Top 5
4. 点「叮一下」→ 调用 `POST /reminders/nudge`
5. 若返回 `NO_QUOTA` → 弹半屏引导：
   ```text
   微信规定：每开一次微信提醒，只能叮一次
   [ 再开一次，帮我把话带到 ]
   [ 算了，先记着 ]
   ```
6. 成功后 toast `已经叮到阿妈啦 🔔` 并返回首页

**校验：** 内容不能为空，最长 200 字。

### P09 派活 `pages/task/create`

```text
┌──────────────────────────────┐
│  ←  派个活                    │
├──────────────────────────────┤
│  干啥？                       │
│  ┌────────────────────────┐  │
│  │ 帮我拿一下快递           │  │
│  └────────────────────────┘  │
│                              │
│  派给谁？                     │
│  ┌────┐ ┌────┐ ┌────┐        │
│  │阿妈│ │阿爸│ │我  │        │  ← 「我」= 自己给自己派
│  └────┘ └────┘ └────┘        │
│                              │
│  什么时候？                   │
│  ┌──────┬──────┬──────┐      │
│  │ 不限 │ 今天 │ 指定 │      │  ← 分段控件
│  └──────┴──────┴──────┘      │
│  今天 18:00          修改 >   │
│                              │
│  重复？                       │
│  ⚪ 不重复  ⚪ 每周  ⚪ 每月   │
│  每周六 18:00                 │  ← 周几由「什么时候」推出，只读回显
│                              │
│  要不要叮一下？                │
│  [ ●━━ ]  18:00 提前提醒       │  ← Switch，默认开
│                              │
│  备注                         │
│  ┌────────────────────────┐  │
│  │ 一楼驿站                 │  │
│  └────────────────────────┘  │
│                              │
│  谁能看见？                   │
│  ⚫ 家里人都能看到  ⚪ 只有我俩 │
│                              │
├──────────────────────────────┤
│        [  派 出 去  ]         │
└──────────────────────────────┘
```

**交互细节：**

1. 「什么时候」默认选中「今天」，时间为当前时间 + 2 小时
2. 「要不要叮一下」默认开启，提醒时间自动 = 截止时间 - 30 分钟（可改）
3. 若 `dueAt` 为空（不限时间），则叮一下开关**与「重复」一起**置灰不可用
   —— 没有时间就推不出「每周六几点」，也不知道提前多久提醒
4. 「重复」的周几 / 几号与时刻**由「什么时候」推出**（`{ weekdays: [6], time: "18:00" }`），
   不再单独问一遍：用户已经说清了「周六 18:00」，重复问既啰嗦又制造两次回答不一致的可能。
   规则以「每周六 18:00」的形式回显，让人一眼能核对
5. 点「派出去」→ `POST /family-things`（type=TASK，带 reminders）
6. 成功后 toast `已经把活派给阿妈啦～`（派给自己时是 `自己的事，记下啦～`），返回首页

**校验：** 标题必填；执行人必选。备注可空。

### P10 小事详情 `pages/thing/detail`

```text
┌──────────────────────────────┐
│  ←                           │
├──────────────────────────────┤
│                              │

│                              │
│  买牛奶                       │
│                              │
│  阿妈 → 阿爸                  │

│                              │

│                              │
│  谁能看见：家里人都能看到      │
│                              │
├──────────────────────────────┤
│  [  搞定啦 ✓  ]  [ 取消 ]     │  ← 主操作按钮
```

**交互细节：**

- 「取消」需二次确认（底部 ActionSheet）：`取消这件事？历史记录会保留`
- 已完成状态 → 显示「重新打开」次要按钮

### P21 微信提醒 `pages/mine/wechat-notify`

**入口：「我的」Tab → 消息与提醒 → 微信提醒**

**这个页面存在的唯一目的：让「叮一下」真的能叮到人。**

```text
【未开启状态】
┌──────────────────────────────┐
│  ←  微信提醒                  │
├──────────────────────────────┤
│         🔔                    │
│   开启后，家里有事会直接       │
│   弹到你的微信里               │
│                              │
│   ┌──────────────────────┐   │
│   │  ① 扫码关注          │   │
│   │     [二维码]         │   │
│   └──────────────────────┘   │
│   ┌──────────────────────┐   │
│   │  ② 把下面这串数字      │   │
│   │     发给我            │   │
│   │                      │   │
│   │      7 3 5 2 4 1      │   │
│   │    10 分钟后过期       │   │
│   └──────────────────────┘   │
│                              │
│   绑定好了会自动跳回来         │
└──────────────────────────────┘

【已开启状态】
┌──────────────────────────────┐
│  ←  微信提醒                  │
├──────────────────────────────┤
│         ✅                    │
│   已经开启啦                   │
│   家里有事会直接弹到你的微信    │
│   2026-10-06 开启              │
├──────────────────────────────┤
│  重新绑定                  >   │
│  关闭提醒                  >   │
└──────────────────────────────┘
```

**交互流程：**

```text
进入页面
   ↓
GET /notify/mp-bind/status
   ├─ bound = true  → 展示「已开启」
   └─ bound = false ↓
POST /notify/mp-bind/code   （生成 6 位绑定码，TTL 10 分钟）
   ↓
展示二维码 + 绑定码
   ↓
每 3 秒轮询一次 GET /notify/mp-bind/status（最多 20 次）
   ├─ 检测到 bound = true → 播放成功动效 → 切换为「已开启」
   └─ 超时 → 提示「还没收到哦，重新获取一个码试试」+ [ 重新获取 ]
```

**文案纪律（重要）：**

| 场景 | 文案 |
| --- | --- |
| 标题 | 「微信提醒」——**不叫「绑定公众号」**，用户不关心技术名词 |
| 价值说明 | 「开启后，家里有事会直接弹到你的微信里」 |
| 未开启提示 | 「还没开」——**不是「未绑定」** |
| 成功 | 「已经开启啦」 |
| 失败 | 「还没收到哦，重新获取一个码试试」 |

**❌ 禁止出现：** 绑定、授权、公众号、openid、订阅、模板消息、测试号。

**兜底：** 用户始终可以只靠「打开小程序看首页」使用全部功能。
**这个页面不开启，产品依然完整可用**——它只是让提醒更及时。

> 完整技术方案见 `docs/08-wxpush推送集成方案.md`。

### 4.1 主链路：吃啥呢 → 派活 → 叮一下 → 完成 → 留个念

```text
① 阿妈打开「吃啥呢」
        ↓
② 点「换一个」转几次，看到「番茄炒蛋 + 炒青菜」
        ↓
③ 点「就吃这个」
        ↓
④ 弹出：派给阿妈 / 派给阿爸 / 不用派
        ↓
⑤ 选「派给阿爸」
        ↓
⑥ POST /menu/decide-and-assign
   ├─ 写入 meal_records（今天晚餐吃什么）
   └─ 创建 family_things（type=TASK，title=今晚做饭：番茄炒蛋、炒青菜）
        ↓
⑦ 阿爸收到微信提醒「🎯 阿妈派了个活给你：今晚做饭」
        ↓
⑧ 阿爸点开 → 小事详情 → 点「搞定啦」
        ↓
⑨ 阿妈收到「❤️ 阿爸已经把「今晚做饭」搞定啦」
        ↓
⑩ 第二天，阿妈在「留个念」发一条：昨晚的番茄炒蛋，宝宝吃了两碗饭
```

### 4.2 新用户首次进入

```text
启动
  ↓
有 token？
  ├─ 否 → wx.login → POST /auth/login
  └─ 是 → 校验有效期
  ↓
families 为空？
  ├─ 是 → 进入引导页
  │        ┌──────────────────────┐
  │        │  家有小事，不必放心上  │
  │        │                      │
  │        │ [ 创建一个家 ]        │
  │        │ [ 加入家人的家 ]      │
  │        └──────────────────────┘
  │              ↓
  │        创建 → 填家庭名 + 我的称谓
  │        加入 → 输邀请码 → 预览家庭 → 填称谓
  │              ↓
  └─ 否 → 进入首页（默认第一个家庭）
```

### 4.3 叮一下的送达链路（四通道降级）

> **v0.2.1 变更：** 不再是「先查订阅额度」，而是**先看对方有没有开微信提醒**。
> 完整方案见 `docs/08-wxpush推送集成方案.md`。

```text
阿妈点「叮一下」
        ↓
POST /reminders/nudge
        ↓
后端按优先级依次尝试：

① 阿爸绑定了微信提醒？
   ├─ 是 → 发公众号模板消息
   │        ├─ 成功     → SENT      「已经叮到阿爸啦 🔔」
   │        └─ 已取关   → 清 openid → 降级 ↓
   └─ 否 ↓

② 阿爸有订阅消息额度？
   ├─ 是 → 发订阅消息
   │        └─ 成功     → SENT
   └─ 否 ↓

③ 写入站内消息中心（永不失败）
   ├─ 阿爸没开微信提醒 → NOT_BOUND「已记下，阿爸还没开微信提醒，他打开小程序就能看到」
   └─ 只是没额度       → NO_QUOTA 「已记下，阿爸再开一次微信提醒就能收到」

无论走哪条，notification_logs 都完整记录（含实际渠道与失败原因）
```

**给发起人的反馈只有三档，但必须说清楚是哪一档：**

| 结果 | 含义 | 发起人看到 |
| --- | --- | --- |
| `SENT` | 已经发到对方微信了 | 「已经叮到阿爸啦 🔔」 |
| `NOT_BOUND` / `NO_QUOTA` | 微信没发出去，但对方打开小程序能看到 | 「已记下，阿爸还没开微信提醒，他打开小程序就能看到」 |
| `FAILED` | 真的失败了 | 「没叮成功，稍后再试」 |

> ⚠️ **「有条件的成功」必须讲清楚条件。** 如果含糊地说「已发送」，发起人会以为对方已经看到了，
> 反而制造误会——这比直接说失败更糟。

## 五、通用状态设计

| 状态 | 处理方式 |
| --- | --- |
| 加载中 | 骨架屏（内容区灰色块），不用全屏 loading |
| 首次空 | 插画 + 一句有人情味的话 + 一个明确按钮 |
| 网络错误 | 顶部轻提示条 + 「重试」按钮，不弹模态框 |
| 无权限 | toast 提示后返回上一页 |
| 提交中 | 按钮置 disabled + 文案变「派出去了…」 |
| 长列表 | 上拉加载，底部「没有更多了」 |
| **对方未开微信提醒** | 顶部轻提示条（**只陈述事实，不催办**）+ 一个轻量出口 → P21 |
| **订阅额度不足** | 顶部轻提示条 +「去授权」；仅在订阅消息是唯一可用通道时出现 |
| **本人未开微信提醒** | 不主动打扰。仅在「我的」Tab 的对应行用 `--warning` 色标识 |

### 5.1 通知状态的可见性（v0.2.1 新增）

「消息中心」的每条通知都带上**实际发送渠道**，避免用户猜：

| 渠道 | 展示 | 含义 |
| --- | --- | --- |
| 公众号提醒 | 灰色小字「已推送到微信」 | 走通道 ①，对方微信收到了 |
| 订阅消息 | 灰色小字「已推送」 | 走通道 ② |
| 仅站内 | 灰色小字「对方打开小程序可见」 | 走通道 ③，微信没推出去 |

> 这不是给用户看的「技术信息」，而是**信任信息**——发起人需要知道「到底叮到了没有」（PRD 6.5.6）。

## 六、文案规范（重要）

产品原则里写明「有人情味」，所以文案必须统一：

| 场景 | ❌ 不要这样写 | ✅ 要这样写 |
| --- | --- | --- |
| 派活成功 | 任务创建成功 | 已经把活派给阿妈啦～ |
| 完成 | 任务状态已变更 | 搞定啦 ✓ |
| 完成通知 | 任务执行完成 | ❤️ 阿爸已经把「买牛奶」搞定啦 |
| 空列表 | 暂无数据 | 今天还没有小事，要不要先叮一下？ |
| 提醒 | 您有一项待办 | 🔔 阿妈喊你拿快递 |
| 出错 | 系统异常 | 出了点小问题，再试一次 |
| 加入家庭 | 操作成功 | 欢迎回家 👨‍👩‍👧 |
| 退出家庭 | 确认退出？ | 要离开「我们家」吗？以前的记录都会留着 |

**绝对禁止出现的词：** 任务逾期、超时未完成、待办事项、审批、流程、KPI、催办、监督、绩效。
