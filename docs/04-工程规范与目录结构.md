**为什么用 monorepo：** 接口出入参类型只写一遍（`packages/shared`），后端改字段时小程序端编译期就能报错，避免联调时才发现对不上。

> **`@jyss/shared` 的引用方式：**
> - `server/tsconfig.json` 与 `miniprogram/tsconfig.json` 都配了 `paths`：`@shared/*` → `packages/shared/src/*`
> - `server/package.json` 用 `"@jyss/shared": "workspace:*"` 建立 workspace 依赖
> - **不需要为 shared 单独构建**，直接引用源码
>
> ⚠️ **两个踩过的坑，改 paths 前必读：**
>
> **① `paths` 的值不要带 `.ts` 后缀。**
> `"@shared": ["../packages/shared/src/index.ts"]` 看着更明确，但 `nest build`
> 会把别名**原样替换**成相对路径并保留后缀，产物里就出现
> `require("../../../../packages/shared/src/index.ts")` —— Node 不认 `.ts`，
> 启动直接 `MODULE_NOT_FOUND`。必须写成 `["../packages/shared/src/index"]`。
>
> **② 构建产物不在 `dist/main.js`，而在 `dist/server/src/main.js`。**
> 因为 `server/tsconfig.json` 的 `include` 同时包含 `src/**` 与
> `../packages/shared/src/**`，tsc 推断出的 `rootDir` 是仓库根目录。
> 编译后的 shared 会一起进 `dist/packages/shared/`，
> 这样重写出来的相对路径才解析得到。**Dockerfile 的 CMD 要与此一致。**

### 2.2 请求封装约定

```ts
// services/request.ts 的核心行为
// 1. 自动带 Authorization
// 2. code === 0 → 返回 data
// 3. 40100/40101 → 静默 wx.login 重新登录，成功后重放一次请求
// 4. 其他非 0 → 抛出带 code/message 的错误，由页面 catch 决定 toast 文案
// 5. 统一 baseURL，从 app.ts 的 globalData 读取（区分 dev/test/prod）
// 6. 请求超时 10s，失败自动重试 1 次（仅 GET）
```

**页面里不允许直接调 `wx.request`。** 这是硬性规范，否则错误处理会散落各处。

### 2.3 分包策略

V0.1 **不分包**。若主包超 2MB（通常是图片资源导致）：

```json
{
  "subpackages": [
    { "root": "pages/family", "name": "family" },
    { "root": "pages/menu", "name": "menu" }
  ],
  "preloadRule": {
    "pages/index/index": { "network": "all", "packages": ["family", "menu"] }
  }
}
```

先不分包的原因：21 个页面都是轻页面，分包带来的 `require` 跨包限制会拖慢开发速度。等真超了再分。

### 3.2 Prisma 命名映射

数据库是 `snake_case`，接口层是 `camelCase`，通过 Prisma `@map` / `@@map` 转换：

```prisma
model FamilyMember {
  id        BigInt   @id @default(autoincrement())
  familyId  BigInt   @map("family_id")
  userId    BigInt   @map("user_id")
  roleName  String   @map("role_name") @db.VarChar(30)
  status    Int      @default(1)
  joinedAt  DateTime @default(now()) @map("joined_at")
  leftAt    DateTime? @map("left_at")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@unique([familyId, userId], map: "uk_family_user")
  @@map("family_members")
}
```

**接口层永远不出现下划线字段。** 转换在 Prisma 层一次性完成。

> ⚠️ **每个字段都必须显式写 `@map`，漏写不会报错，但后果很严重。**
> 漏了 `@map` 时，Prisma 认为列名就是 camelCase 字段名本身，于是：
>
> - `prisma db push` 会尝试把列名改成 camelCase（`DROP COLUMN` + `ADD COLUMN`，**丢数据**）
> - 更隐蔽的是，即使不 push，运行时查询也会报 `Unknown column 'xxx'`
>
> 2026-10-06 实测踩到过一次：`users.mp_openid` 与 `family_invites.invite_code`
> 两个字段漏了 `@map`，会导致**邀请功能与公众号绑定全部失效**。
>
> **自查命令**（输出必须是 `-- This is an empty migration.`）：
>
> ```bash
> cd server && pnpm exec prisma migrate diff \
>   --from-url "$DATABASE_URL" \
>   --to-schema-datamodel prisma/schema.prisma \
>   --script
> ```
>
> 这条命令是 `schema.prisma` 与 `db/schema.sql` 是否真正对齐的**唯一可靠判据**，
> 改了任一边之后都应该跑一次。

### 3.3 pnpm 构建脚本白名单

**pnpm 10+ 不再读 `package.json` 里的 `pnpm` 字段**，构建脚本白名单必须写在
`pnpm-workspace.yaml`：

```yaml
allowBuilds:
  '@prisma/client': true
  '@prisma/engines': true
  prisma: true
```

漏配的后果：Prisma 的 `postinstall` 被静默跳过 → `@prisma/client` 不生成 →
`prisma:push` / `prisma:generate` 直接失败，报 `ERR_PNPM_IGNORED_BUILDS`。

> pnpm 11 检测到被忽略的构建脚本时，会**自动**在 `pnpm-workspace.yaml` 写入占位符
> （`'@prisma/client': set this to true or false`）。看到这种字样，把值改成 `true` 即可。

- **禁止 `console.log`**，统一用 NestJS `Logger`（后端）/ 自研 `logger`（小程序端）
- **禁止硬编码密钥**，全部走环境变量
- **禁止在前端做数据权限过滤**，必须在服务端完成
- **小程序端不能 `import` `@shared` 的运行时值，只能 `import type`**
  - 微信开发者工具的 TypeScript 编译插件由 `@babel/plugin-transform-typescript` 实现，

    文件头写明权威来源，并由 `node tools/check-shared.mjs` 逐个比对防漂移。
  - 镜像用 `as const` 对象而不是 `enum` —— `@babel/plugin-transform-typescript`
    默认不转换 `enum`，直接写 `enum` 有编译风险。
- 函数长度尽量 ≤ 50 行，超过就拆
- 单个文件 ≤ 400 行

## 六、Git 规范

### 6.1 分支策略

```text
main        ← 生产分支，只接受来自 release 的合并，每个提交都可上线
  ↑
develop     ← 集成分支，日常开发合并到这里
  ↑
feat/*      ← 功能分支
fix/*       ← 修复分支
chore/*     ← 杂项
```

个人项目可以简化为 `main` + `feat/*`，但保留 `develop` 的好处是：可以随时在 `main` 上打 tag 发版本，而不影响正在开发的功能。

### 6.2 提交信息规范

```text
<type>(<scope>): <subject>

type:  feat | fix | docs | style | refactor | perf | test | chore
scope: auth | family | thing | reminder | menu | memory | upload | notify | mp | wxpush | db | tools
```

> `tools` 专给仓库根 `tools/` 下的自查与冒烟脚本（`check-ts` / `check-links` /
> `smoke-*` / `probe-*`）。它们不属于任何业务模块，硬塞 `server` 或 `db` 会让
> 「按 scope 找改动」失效。

示例：

```text
feat(thing): 支持创建派活时同时挂定时提醒
fix(reminder): 修复重复提醒计算下一次时间时区偏移问题
docs(api): 补充订阅额度上报接口
chore(db): 初始化 11 张核心表
feat(mp): 微信提醒绑定码生成与轮询
feat(wxpush): 中转页支持小程序码长按识别
test(tools): 新增 M1 家庭链路端到端冒烟脚本
```

### 7.1 敏感等级与交接约定 ⭐

不同变量的敏感度差别很大，**不要一视同仁**：

| 等级 | 变量 | 存哪 | 能否写进对话 / 文档 |
| --- | --- | --- | --- |
| 🟢 **公开** | `WX_APPID`（小程序 AppID） | `miniprogram/project.config.json`（**要提交**） | ✅ 可以 —— AppID 本身就是公开标识 |
| 🟢 **公开** | `WX_ENV_ID` / `MP_APPID` / `MP_PAGEPATH` / `MP_NAME` | `.env` 或文档 | ✅ 可以 |
| 🔴 **机密** | `WX_SECRET`、`MP_CALLBACK_TOKEN`、`JWT_SECRET`、`INTERNAL_CRON_SECRET`、`DATABASE_URL`（含密码）、`COS_SECRET_ID` / `COS_SECRET_KEY`、`WXPUSH_TOKEN`、Worker 的 `WX_SECRET` | **只放 `.env`（已 gitignore）或云托管控制台** | ❌ **绝不** |

**两条硬规矩：**

1. **`WX_SECRET` 只能出现在服务端。** 小程序端代码里出现 AppSecret = 密钥泄露（前端代码可被反编译）。
2. **不需要向任何人「报备」密钥。** 代码读的是环境变量，你只要把值填进
   `server/.env`（本地）或云托管控制台（生产），代码不需要知道具体值。

> 💡 **可以自己生成的**（不用等微信，也不需要告诉我）：
> ```bash
> openssl rand -hex 32     # JWT_SECRET / INTERNAL_CRON_SECRET / Worker 的 API_TOKEN
> ```

## 八、本地开发环境

### 8.1 `docker-compose.yml`（仓库根目录，已就绪）

包含 MySQL 8.0（自动执行 `db/schema.sql` 建表，时区固定 `+00:00`，见 docs/01 §4.3）与 Redis 7，均带 healthcheck。

```bash
pnpm run db:up      # 起库
pnpm run db:down    # 停库（保留数据）
pnpm run db:reset   # 停库并清空数据（改了 schema.sql 后重新建表用）
```

> ⚠️ MySQL 的 initdb 脚本**只在数据卷首次创建时执行**。改了 `db/schema.sql` 必须 `db:reset`。

### 8.2 启动步骤

```bash
# 1. 起数据库
pnpm run db:up

# 2. 安装依赖（根目录）
pnpm install

# 3. 准备环境变量
cp server/.env.example server/.env     # 然后填真实值

# 4. 生成 Prisma Client + 同步表结构
cd server && pnpm run prisma:push

# 5. 起后端
pnpm run dev          # http://localhost:3000

# 6. 起小程序
# 用微信开发者工具打开 miniprogram/ 目录
# 在「详情 → 本地设置」勾选「不校验合法域名」
```

### 8.3 开发时怎么实时预览 ⭐

三样东西要在**三个不同的地方**看，互不干扰：

| 对象 | 在哪看 | 改动后如何刷新 |
| --- | --- | --- |
| **小程序端** | 微信开发者工具（本机） | **保存文件即自动重编译**，不用手动操作 |
| **后端** | 终端（`pnpm run dev`） | `nest start --watch`，改代码自动重启 |
| **原型 HTML** | 浏览器打开 `prototypes/prototype.html` | 手动刷新 |

#### 小程序端首次导入

1. 打开微信开发者工具 → **导入项目**
2. **目录**：选仓库里的 `miniprogram/`（不是仓库根目录）
3. **AppID**：填你的真实 AppID（见 `docs/06` 1.4）
4. **详情 → 本地设置** → 勾选
   **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
   > 本地后端是 `http://localhost:3000`（非 HTTPS），不勾选会直接被拦。

#### 三种预览模式

| 模式 | 入口 | 说明 |
| --- | --- | --- |
| **模拟器** | 工具左侧面板 | 日常开发最常用，改完即见 |
| **真机预览** | 工具栏「预览」→ 手机扫码 | **必须有真实 AppID**；能看到真实机型表现 |
| **真机调试** | 工具栏「真机调试」 | 可在真机上看 console / network，排查真机特有问题 |

#### 两条必须知道的约束

1. **TypeScript 由开发者工具内置编译**（`project.config.json` 里 `useCompilerPlugins: ["typescript"]`），
   **不需要**单独跑 `tsc`，也不要手动提交编译产物。
2. **没有真实 AppID 走不通登录链路。**
   开发者工具的「无 AppID」模式只能看静态页面——`wx.login` 拿不到 `code`，
   `POST /auth/login` 必然失败。**M1 第一条链路就必须有真实 AppID。**

## 九、后端 Dockerfile

见 `server/Dockerfile`（已就绪）。要点：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 基础镜像 | `node:22-alpine` | ⚠️ Node 20 已 EOL，不要再用 |
| 时区 | `TZ=Asia/Shanghai` | 不设的话接口层格式化出来的就不是北京时间（存储用 UTC，见 §4.3 与 docs/01 §4.3） |

## 十、代码审查自查清单

提交 PR 前自查：

- [ ] 接口出入参是否与《02 API 接口设计》一致？不一致是否已同步更新文档？
- [ ] 是否有硬编码的密钥 / host / appid？
- [ ] 数据权限过滤是否在服务端完成？
- [ ] 新增/修改的接口是否有 DTO 校验？
- [ ] 涉及时间的地方是否走了 `common/serialize/beijing-time.ts`，而不是自己 `toISOString()`？
- [ ] 涉及金钱/额度的地方是否有幂等保护？
- [ ] 是否写了 `console.log`？
- [ ] 文档是否需要同步更新？

**改动后端接口时额外自查：**

- [ ] 是否跑过 `node tools/smoke-m1.mjs`？**「编译通过」不等于「链路通」** ——
      接口层的问题（权限过滤、错误码、时间序列化、邀请码状态机）只有真实打到
      数据库才能暴露。脚本会连本地 MySQL 建夹具并逐条断言 `code`。
- [ ] 新增的错误码是否已在 `docs/02 §1.2` 登记？文案是否避开了禁用词（AGENTS.md §6）？

**改动小程序页面 / 组件时额外自查：**

- [ ] 是否跑过 `node tools/check-mp.mjs`？小程序有一类错误**编译不报、`tsc` 也不报**，
      只在运行时安静地失效：页面文件少一个（白屏）、`bindtap` 绑错方法名（点了没反应）、
      写了页面忘了在 `app.json` 注册（路由跳不过去）、`usingComponents` 路径写错（整个页面白屏）、
      **未读角标挂到别的 Tab 上**（`setTabBarBadge` 只认下标）。
      ⚠️ 输出末尾的 `⏳` 行**不算失败**，是「还没配好但页面有降级」的提示
      （目前只有一条：微信提醒页的二维码）。
      **组件和页面一样会被扫**——组件写错了，报错指向组件而不是出问题的那一行。
- [ ] 页面里是否直接调了 `wx.request`？（不允许，只能走 `services/request.ts`）
- [ ] 是否 `import` 了 `@shared` 的运行时值？（只能 `import type`，见 §5.2）
- [ ] 自定义组件抛事件时，名字是不是避开了原生事件名？（`triggerEvent('tap')` 会和原生 tap
      冒泡撞车，页面写 `bindtap` 会收到两次回调）
- [ ] 展示模型（`utils/*-view.ts`）是不是保持**纯函数**了？有 `wx.*` 副作用的东西
      （如 `utils/tab-badge.ts`）要单独放 —— 混进去就没法断言了。
- [ ] 改了 `utils/thing-view.ts` / `utils/notice-view.ts` / `utils/mine-view.ts`
      （或任何纯展示逻辑）后，是否跑过 `node tools/test-view.mjs`？
      **这一类函数编译不报、类型也对，
      错的是「意思」** —— 比如把 `describeDue(null)` 拼成「不限时间前完成」，
      或者给创建者一个点了就 403 的「退出家庭」按钮。
      写这个断言工具的当天它就抓到一个空格级别的文案错误。
      **别只加断言，也要顺手核对既有断言还成不成立**：文案改了而断言没改，
      测试就变成了新的「已知偏差」。

**涉及推送时额外自查（见 `docs/08`）：**

- [ ] 推送失败是否会**阻塞主流程**？（不允许：必须降级 + 写日志）
- [ ] `notification_logs` 是否**无条件写入**？（站内兜底是产品承诺，不能省）
- [ ] 给发起人的反馈是否**区分了三档**（SENT / NOT_BOUND·NO_QUOTA / FAILED）？
- [ ] 是否直接调用了 `wxpush` / 微信 API，绕过了 `notify.service.ts`？（不允许）
- [ ] 文案里是否出现了「绑定 / 授权 / 公众号 / openid / 订阅 / 模板消息 / 测试号」？（用户不该看到这些词）
- [ ] 新写的推送逻辑是否**不依赖** `NOTIFY_MP_ENABLED=true` 也能正常工作？
