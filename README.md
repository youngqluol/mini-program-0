# 家有小事

> **家有小事，帮你记着、分着、决定着。**

面向家庭成员的轻量事务协作微信小程序。

不追求功能多，只解决三件事：**重要的事不会忘记 / 事情有人负责 / 纠结的事不再纠结。**

---

## 四个模块

```text
🔔 叮一下  ——  别忘了
🎯 派个活  ——  有人做
🍽️ 吃啥呢  ——  别纠结
📖 留个念  ——  值得记
```

核心闭环：

```text
🍽️ 吃啥呢  →  决定吃什么  →  🎯 派活  →  指定家人
     ↓
🔔 叮一下  →  对方收到  →  ✓ 完成  →  ✨ 搞定啦  →  📖 留个念
```

---

## 三条不可动摇的纪律

```text
① 只提醒，不监督。
   没有催办、没有逾期处罚、没有强制确认。

② 家庭不是公司。
   没有审批、没有工作流、没有 KPI、没有权限矩阵。

③ 功能只减不增。
   V0.1 的任何新想法，写进 docs/未来需求池.md，不要写进代码。
```

## 技术栈

| 层次 | 选型 |
| --- | --- |
| 小程序端 | 原生微信小程序 + TypeScript |
| 后端 | NestJS（Node 22 LTS）+ Prisma |
| 数据库 | 微信云托管 MySQL 8.0（11 张表） |
| 缓存 | 腾讯云 Redis（内网调用） |
| 存储 | 云开发云存储 / COS |
| 部署 | 微信云托管（容器，自定义 Dockerfile） |
| 推送 | 四通道降级：公众号模板消息（wxpush）→ 小程序订阅消息 → 站内消息 → 首页 |

> **为什么后端选 NestJS？** 前后端同语言，`packages/shared` 里的类型改一处、两边编译期同时报错；
> 一个业务域一个 module，天然匹配领域划分；个人开发者最贵的是调试时间，而不是服务器钱。
> 详见 `docs/01-技术架构与技术选型.md`。

## 快速开始

```bash
# 0. 前置：Node 22+ / pnpm 9+ / Docker Desktop

# 1. 起本地数据库（首次会自动执行 db/schema.sql 建表）
pnpm run db:up

# 2. 安装依赖
pnpm install

# 3. 准备环境变量
cp server/.env.example server/.env
# 然后填入真实值（WX_APPID / WX_SECRET / JWT_SECRET 等）

# 4. 同步表结构到 Prisma
cd server && pnpm run prisma:push

# 5. 起后端
pnpm run dev          # http://localhost:3000

# 6. 起小程序
# 用微信开发者工具打开 miniprogram/ 目录
# 在「详情 → 本地设置」勾选「不校验合法域名」
```

> `pnpm install` 前请注意：`server/package.json` 里的依赖版本是**起始值**，
> 首次安装时若提示某个版本不存在，把它升到当前最新即可（M1 阶段会统一锁一次版本）。

## 开发路线

```text
M0 准备就绪   ← 你在这里
   ↓
M1 骨架贯通   登录 → 建家 → 邀请 → 加入
   ↓
M2 核心闭环   派活 + 叮一下 + 完成   ★ 最关键
   ↓
M3 吃啥呢     随机决策 + 一键派活
   ↓
M4 留个念     图片发布 + 家庭时间线
   ↓
M5 上线       提审 → 发布 → 家人真机安装
```

## 现在最该做的四件事

1. **申请小程序账号 + 订阅消息模板**（卡审核，第一天就提交）
2. **搭本地环境**（`pnpm run db:up`）
3. **跑通 M1 第一条链路**（登录 → 建家 → 邀请 → 加入）
4. **搭起推送通道**（wxpush，决定产品成不成立）

完整清单见 `docs/README.md`。
